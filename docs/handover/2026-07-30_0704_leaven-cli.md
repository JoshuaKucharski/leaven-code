## Was das Projekt ist
Deutschsprachiger CLI-Agent (`~/develop/platforms/leaven/leaven`, `src/index.ts` ~2920 Z.) für
**mehrere LLM-Provider**. Nutzer stellt Aufgabe → Modell fordert Werkzeuge an → CLI führt sie
**in harten Grenzen** aus. **Sprache: Befehle englisch, alles andere (Ausgaben/Kommentare/Doku)
deutsch.** Kein git-Repo. Node/TypeScript, Build `npm run build` (tsc).

`axios` (Lieferketten-Sicherheit). Provider-Erkennung + Fähigkeiten in `src/providers/capabilities.ts`.

## Die NICHT verletzbaren Invarianten (Details: leaven-cli/development-advices.md)
1. `reasoning_content`/`thinking`-Blöcke **unverändert** zurückreichen; Modell/Thinking **nicht**
   mitten in einer Konversation wechseln → sonst HTTP 400. (`/model`,`/thinking` resetten den Verlauf.)
2. Rohes Antwortobjekt **unverändert** in die History pushen.
3. Pfade zählen **immer** ab dem Lesebereich; `securePath()` ist symlink-fest.
4. **Rechte sind modellunabhängig** — die CLI erzwingt sie, nicht das Modell.
5. **Streaming:** vollständige Message ODER werfen; `content` nie live drucken (nur Reasoning).
6. `~/.leaven` ist AI-dicht; nur der Mensch gibt Befehle/Skripte frei.
7. Interpreter (`php`/`git`/`bash`) nie pauschal auf die Allowlist.
8. `post_to_endpoint`: genau eine Ziel-URL, keine Weiterleitungen.
9. Session-Speicherpunkt (Auto-Stopp, Schleifenkopf) ist **immer** API-gültig (jeder tool_call beantwortet).

## Arbeitsweise, die trägt (der Nutzer legt Wert darauf)
- **Belegt statt behauptet**: Vermutungen messen, bevor man sie als Ursache benennt.
- Ehrlich zwischen „behoben" und „gemildert" unterscheiden; eigene Fehler benennen.
- **Keine neuen Abhängigkeiten** für Provider/Netz — alles über `axios`.
- Für heikle Teile (Streaming, Persistenz) **Fable-Subagent als Reviewer** einsetzen — hat mehrfach echte Bugs gefunden.
- Führender Schrägstrich in Nutzer-Pfaden (`/docs/…`) = **projektrelativ**.
- **`.env` enthält nur Platzhalter**; echte Keys in `~/.zshrc`. `. ./.env` beim Testen zerschießt den echten Key.
